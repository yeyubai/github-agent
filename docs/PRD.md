# GitHub Agent 产品需求文档

## 1. 产品概述

### 1.1 产品定位

**GitHub Agent** 是一个面向个人开发者的智能 GitHub 管理工具。通过自然语言对话（AI）+ `gh CLI` 的组合，让开发者用"说话"的方式完成 GitHub 上的日常操作和效率任务。

### 1.2 目标用户

独立开发者、自由职业者、小型团队技术成员。

### 1.3 核心价值主张

- **零学习成本**：不用记 gh CLI 命令，用自然语言描述需求即可
- **效率场景驱动**：聚焦日报/周报生成、代码变更摘要、待办追踪等高频个人场景
- **本地安全可控**：gh CLI 在本地执行，API Key 不上传第三方

### 1.4 技术栈

| 层级 | 技术 |
|------|------|
| 框架 | Next.js 16 (App Router) |
| UI | shadcn/ui + Tailwind CSS v4 |
| AI | DeepSeek Chat (deepseek-chat) |
| GitHub 集成 | GitHub CLI (gh) |
| 语言 | TypeScript + React 19 |

### 2.2 详细功能需求

#### F1. Agent 对话（核心）

**用户故事**：作为开发者，我希望用自然语言告诉 Agent 我想做什么（如"帮我看看上周提交了什么"），Agent 自动执行 gh 命令并返回结果。

**功能规格**：
- 流式输出响应，用户无需等待完整回复
- Agent 能识别意图并执行对应的 gh 命令
- 执行破坏性操作（如关闭 Issue、合并 PR）前需用户确认
- 支持多轮对话，上下文自动传递
- 对话历史本地持久化，刷新不丢失

**验收标准**：
- [ ] 用户输入"查看我的仓库"，Agent 展示仓库列表
- [ ] 用户输入"上周我提交了哪些 PR"，Agent 展示 PR 列表
- [ ] 用户输入"帮我创建一个 Issue"，Agent 引导填写标题/描述
- [ ] 对话刷新后历史记录仍在

#### F2. 仓库管理

**用户故事**：作为开发者，我想快速浏览和管理我的 GitHub 仓库。

**功能规格**：
- 仓库列表页：展示名称、描述、语言、Star 数、更新时间
- 支持按语言/更新时间/Star 数排序
- 支持按关键词搜索
- 仓库详情页：README 渲染、最近提交、主要语言占比

**验收标准**：
- [ ] 列表页加载时间 < 3 秒
- [ ] 排序和筛选即时响应
- [ ] 详情页 README 正确渲染 Markdown

#### F3. PR 管理

**用户故事**：作为开发者，我想方便地跟踪和管理我的 Pull Request。

**功能规格**：
- PR 列表：状态筛选（open/closed/merged）、按仓库过滤
- PR 详情：标题、描述、变更文件、评论、审查意见
- 代码 diff 可视化

**验收标准**：
- [ ] 能按仓库筛选 PR
- [ ] PR diff 能正常展示

#### F4. Issue 管理

**用户故事**：作为开发者，我想高效管理 Issue，包括创建、查看、评论。

**功能规格**：
- Issue 列表：状态筛选、标签过滤
- Issue 详情：描述、评论、标签
- 支持通过 Agent 创建新 Issue（对话式引导）

**验收标准**：
- [ ] 能通过对话创建 Issue
- [ ] Issue 列表支持标签筛选

#### F5. 效率工具

**用户故事**：作为开发者，我希望 Agent 能帮我自动生成代码变更摘要、日报周报等。

**功能规格**：
- **代码变更摘要**：Agent 基于 `gh pr view` / `gh api` 结果，自动生成变更摘要
- **日报/周报**：基于最近提交、PR、Issue 活动，AI 自动生成报告
- **待办追踪**：从 Issue/PR 中自动提取待办事项，展示为清单

**验收标准**：
- [ ] 用户输入"生成本周周报"，Agent 输出一份结构化的周报
- [ ] 代码变更摘要能准确列出修改的文件和变更量
- [ ] 待办清单与 Issue/PR 状态同步

#### F6. 设置

**用户故事**：作为开发者，我想配置 AI 模型和 GitHub 账号。

**功能规格**：
- DeepSeek API Key 配置
- GitHub 账号信息展示（当前 gh auth 状态）
- AI 模型选择（后续支持多模型切换）

**验收标准**：
- [ ] 能切换 API Key 并测试连接
- [ ] 显示当前 GitHub 登录用户

## 3. 非功能需求

### 3.1 性能
- 首屏加载 < 2 秒
- API 响应 < 3 秒（gh CLI 执行）
- AI 流式输出首字响应 < 1 秒

### 3.2 安全
- API Key 仅存于服务端（.env.local），不暴露给客户端
- gh CLI 命令执行需白名单校验，禁止危险命令（rm、push --force 等）
- 所有 gh 命令执行需用户确认（破坏性操作）

### 3.3 可用性
- 开发环境零配置启动（除 .env.local）
- gh CLI 未安装或登录时，给出明确引导
